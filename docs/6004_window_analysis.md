# WorkBuddy 6004 频率限制 · 滑动窗口画像与解析陷阱

> 沉淀自 2026-09-09 ~ 2026-09-13 的本地 6004 实测。诊断工具见 `scripts/analysis/find_6004_events.py`（已修时区）与 `scripts/analysis/probe_6004_window.py`（反推定档）。

## 一、结论速览（三档限流画像 · 实测定案）

| 模型 | 窗口长 | 备注 |
|---|---|---|
| `deepseek-v4.1-flash` | **日窗 24h**（滑动，锚点随首用浮动） | 多样本互证，误差 ≤6s |
| `hy4-preview` | **日窗 24h** | 仅 2026-09-13 那次实测定案；早期（09-09/09-10）reset 为同日（约 3–4h），限额策略不同或异账号，**不可一概定 24h** |
| `hy3` | **短窗 <3h** | 精确值未定（样本不足） |

⚠️ 跨账号比「积分/百万 token」无意义；各模型**每日限额**是核心差异，按 (账号, 模型, 触顶天数) 三维分别看。

## 二、关键实测数据（2026-09-13 主样本）

- **触发（北京）**：2026-09-13 12:53:35（日志 UTC `04:53:35` +8）
- **重置（北京）**：2026-09-14 01:44:40
- **窗口内首条请求（北京）**：2026-09-13 01:44:35
- **校验**：首请求 + 24h = 01:44:35 ≈ 重置 01:44:40（误差 5s）→ 完美命中「重置 − 窗口长 ≈ 窗口首请求」规律
- **窗口内请求数（容量参考）**：57 次（代理指标，与脚本统计一致）
- **重置锚点归因**：请求相关性 ID `699877e0` → 01:44:40 一致✅（该 32hex 是每次请求相关性 ID，**不是账号 ID**）

## 三、6004 本质（必读）

1. **硬阻断**：`statusCode:429, code:6004, category:quota`。模型直接不可用，**「消耗积分继续」无效**（若按量计费付钱即可继续，实证否定）。
2. **计量单位 = 用户请求次数**（非 token / 积分）：一次用户请求内部上百次 LLM 调用、近亿 token 仍只算 1 次。容量 N 跨事件 8–14（hy3）至 57（hy4），因模型而异。
3. **滑动窗口限流**：重置时刻 = 窗口内某条请求 + 窗口长（W）；W 按模型不同（hy3 <3h，ds/hy4 = 24h）。同绑定未滑出前再次触顶，重置时刻不变。
4. **本地不可观测**：`credit_ledger` 只记成功+计费请求，被 429 拒绝的不入账 → 账本完全看不到 6004；本地唯一检测手段是扫描 SDK 对话日志。

## 四、解析陷阱（自写脚本必读，已踩）

1. **时间戳在行首文本**：`2026-09-06T14:47:20.929Z method:sendPrompt {...}` —— **不是 JSON 字段**，别按 `\"timestamp\"` 正则解析。
2. **日志时间一律 UTC**，展示/计算必须 +8 转北京时间；重置时间从日志文本 `... UTC+8` 提取已是北京 → **同一张表勿混用时区**（旧 `find_6004_events.py` 的 bug，已修）。
3. **6004 真实信号** = `statusCode:429,code:6004,category:quota`（常嵌在 `runtime.applyStopReason` 的 `errorMessageMetaPreview` 字符串里）；**错误文本不含模型名**（只有"切换其他模型"提示）→ 触发模型只能取「触发时刻之前、同文件最近一次 sendPrompt 的 modelId」，不可用文件末尾方向的 `last_model`（会话换模型会错归）。
4. **模型名有 `-f` 后缀变体**（如 `hy4-preview` / `hy4-preview-f`），归一化后再匹配。
5. **账号不可归因**：会话文件名 `<convId>` = `sessions.id` 可直接 join 标题/模型/创建时间；但 `sessions.user_id` 每次切号被对齐改写为当前 uid，历史归属只能用 auth 备份文件名时间戳 + 文件内 `account.uid` 二分。

## 五、脚本用法

```bash
# 扫描全部 6004 事件（触发/重置均显示北京时间）
USERPROFILE=C:/Users/WH python scripts/analysis/find_6004_events.py --recent 7

# 反推滑动窗口长 + 首请求 + 定档三档画像
USERPROFILE=C:/Users/WH python scripts/analysis/probe_6004_window.py --model hy4-preview
```

注：`USERPROFILE` 显式传入是因为 Git Bash 下 `$USERPROFILE` 常被 mangled；两脚本只读 `~/.workbuddy/logs`，不写任何数据。

## 六、处置建议

- 切其他模型（最快）
- **切账号**（wb-switch 核心价值：每账号独立限额，切过去立即恢复）
- 等重置（按本表窗口长推算）
- 监控 = 检测 6004 事件 + 错峰切号；无法命中前预测（本地无剩余次数可读字段）
